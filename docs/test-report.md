## 4. 本次测试发现并修复的缺陷

| ID | 级别 | 缺陷 | 修复 |
|----|------|------|------|
| D-001 | P1 | 注册/登录成功后 Header 仍显示「登录/注册」（HeaderAuth 只在挂载时拉取登录态，`router.refresh()` 不触发重取） | `header-auth.tsx` 改为随路由变化重新拉取 `/api/auth/me`；已由 AUTH-001/004/005/008 回归验证 |
| D-002 | P2 | 集成测试并行运行时，远端测试库延迟叠加导致默认 5s 超时偶发失败 | Vitest `testTimeout` 调整为 15s |
| D-003 | P2 | E2E 在 dev 模式下按需编译详情路由耗时不稳定，且长跑后 dev server 卡死 | E2E 切换为生产构建模式（`build && start`），消除编译方差并贴近线上行为 |
| D-004 | P2 | 登出后立即跳转存在竞态（登出动作未完成即导航） | 新增公共步骤 `logoutUser`（点击退出并等待 UI 恢复未登录态） |
| D-005 | P2 | E2E 夹具文章引用管理员，集成测试全量清理用户违反 FK RESTRICT | 集成测试按外键依赖顺序清理测试库 |

## 5. 已知缺陷（跟踪中，不阻断上线）

| ID | 级别 | 说明 |
|----|------|------|
| SITE-004 | P1 | 动态路由（文章/工具/商品详情）`notFound()` 在生产环境返回 HTTP 200 而非 404。已实验确认是 Next.js 15.5.29 框架缺陷（上游 issue vercel/next.js#99343、#99318，均未修复）：静态 404 与顶层未匹配路径状态码正确，动态段运行时 notFound 状态码始终为 200。页面内容（404 UI、文案、引导链接）完全正确。处置：用 `test.fail` 跟踪，升级修复版本的 Next 后用例自动转绿 |
