# ValuePass 测试计划

> 状态：初稿（随开发补充用例）
> 版本：v0.1　日期：2026-11-05
> 依据：`docs/prd.md`、`docs/high-level-design.md`、`docs/detailed-design.md`
> 说明：本文档定义测试策略、范围、环境和验收映射；完整测试用例随模块开发逐步补充，最终执行结果写入 `docs/test-report.md`。

## 1. 测试目标

1. 验证 ValuePass 第一版 P0 功能符合 PRD 验收标准。
2. 尽早发现注册登录、后台发布、图片上传和内容展示中的关键缺陷。
3. 保证桌面端与手机端的核心路径可用。
4. 验证 SEO、百度统计、性能与基础安全要求。
5. 为上线决策提供可复核的测试结果。

## 2. 测试范围

### 2.1 本期覆盖（In Scope）

- 首页、AI 全栈、AI 工具、经验分享、商品、关于我
- 注册、登录、退出、禁用账号、登录锁定、手动重置密码
- Studio 后台：文章、工具、商品、精选、用户管理
- Markdown 编辑与渲染
- Vercel Blob 图片上传
- 404、空状态、错误提示
- SEO：metadata、sitemap、robots、JSON-LD
- 百度统计与 2 个自定义事件
- 响应式、性能、可访问性、基础安全

### 2.2 本期不覆盖（Out of Scope）

- 在线支付、购物车、订单
- 评论、论坛、社区互动
- 英文版
- 小程序 / App
- 自助找回密码（仅人工重置）
- 站内搜索（P1，本期不实现）
- 邮件通知、短信验证

## 3. 测试分层

| 层级 | 工具 | 覆盖内容 | 执行时机 |
|------|------|----------|----------|
| 单元测试 | Vitest | slug、摘要、阅读时长、日期、校验 Schema、错误码、密码规则 | 每次提交 |
| 集成测试 | Vitest + 测试数据库 | 注册/登录/锁定、Server Actions、数据查询、精选排序 | 每次提交或每日 |
| E2E | Playwright | 前台核心路径、认证、后台 CRUD、上传、权限、异常状态 | 每次合并前 |
| 视觉回归 | Playwright 截图 | 首页、文章、工具、商品、关于、登录、后台关键页 | 每个里程碑 |
| 性能 | Lighthouse / Vercel 指标 | LCP、CLS、INP、首屏 JS | 上线前 |
| 安全 | 手工 + 自动化 | 权限、限流、XSS、上传、Cookie、SQL 注入防护 | 上线前 |
| 可访问性 | 手工 + Playwright | 键盘、焦点、ARIA、对比度、移动端触控 | 每个里程碑 |
| SEO | 手工 + 抓取检查 | metadata、sitemap、robots、JSON-LD、canonical | 上线前 |
| 统计 | 手工 | 百度统计加载、2 个自定义事件 | 上线前 |

## 4. 测试环境与数据

### 4.1 环境

| 环境 | 用途 | 说明 |
|------|------|------|
| Local | 开发自测 | 本地 Next.js + 测试数据库 + 测试 Blob Token |
| Preview | 集成与验收 | Vercel Preview，禁止写生产数据 |
| Production | 上线冒烟 | 只执行只读与关键路径冒烟 |

### 4.2 测试数据

- 管理员：通过种子脚本创建，使用独立测试账号
- 普通用户：`user_active`、`user_disabled`
- 锁定用户：连续失败 5 次后验证
- 文章：已发布 AI 全栈、已发布经验分享、草稿各 1 篇
- 工具：已发布、草稿各 1 个
- 商品：上架 2 个、下架 1 个
- 精选：文章、工具、商品各 1 个
- 图片：JPG、PNG、WebP 各 1 张；超 5MB、非图片各 1 个
- Blob 测试文件统一使用 `valuepass/test/` 前缀，测试后清理

### 4.3 数据隔离

- 测试数据库与生产数据库分离
- 不在生产环境执行创建、删除、禁用、重置密码等写操作
- 自动化测试不得使用真实用户数据
- 测试产生的 Blob 文件与数据库记录需可识别并清理

## 5. 用例编号与优先级

| 前缀 | 模块 |
|------|------|
| `AUTH` | 注册、登录、退出、会话、限流 |
| `HOME` | 首页与精选 |
| `ART` | 文章列表与详情 |
| `TOOL` | 工具列表与详情 |
| `PROD` | 商品列表与详情 |
| `ADMIN` | Studio 后台 |
| `UP` | 图片上传 |
| `SEO` | SEO |
| `STAT` | 百度统计 |
| `SITE` | 404、空状态、错误页 |
| `SEC` | 安全 |
| `PERF` | 性能 |
| `A11Y` | 可访问性与响应式 |

优先级：

- **P0**：上线阻断，必须全部通过
- **P1**：核心功能，必须在发布前通过
- **P2**：一般问题，可排期修复
- **P3**：轻微问题，可记录后处理

## 7. 核心测试场景

### 7.1 认证（AUTH）

- 注册成功、自动登录、跳转正确
- 用户名重复、密码不足 8 位、两次密码不一致
- 登录成功、密码错误、账号不存在、统一错误提示
- 连续 5 次失败锁定 15 分钟
- 禁用账号无法登录
- 退出后 Session 失效
- 过期 Session 视为未登录
- HeaderAuth 正确显示登录/未登录状态
- `redirectTo` 只允许站内路径

### 7.2 首页（HOME）

- 四板块入口跳转正确
- 精选文章/工具/商品按排序展示
- 最多展示 4 条
- 无精选时展示最新 4 篇文章
- 深色工具区与商品区内容正常
- 手机端导航可用

### 7.3 文章（ART）

- 列表只显示已发布文章
- 详情页标题、摘要、时间、阅读时长正确
- 目录滚动定位正常
- 默认封面生效
- 草稿/不存在返回 404
- Markdown 代码块、列表、引用正确渲染
- 原始 HTML 被清洗
- 上一篇/下一篇或返回列表链接正确

### 7.4 工具（TOOL）

- 列表只显示已发布工具
- 详情字段完整
- 官网按钮新窗口打开且带安全属性
- 点击官网触发百度统计事件
- 草稿返回 404

### 7.5 商品（PROD）

- 列表只显示上架商品
- 详情多图切换正常
- 微信二维码弹窗展示 `dxl20061110`
- 复制微信号成功
- 弹窗 Esc / 遮罩 / 关闭按钮均可关闭
- 已下架商品显示提示与他人推荐，页面 noindex
- 页面不出现价格、购物车、支付入口

### 7.6 后台（ADMIN）

- 未登录访问 `/studio/*` 被拒绝
- 普通用户无法进入后台
- 文章新建、保存草稿、发布、撤回、删除
- 工具新建、编辑、发布、删除
- 商品新建、多图、排序、上架、下架、删除
- 精选勾选、取消、上移、下移
- 用户列表、禁用/启用、重置密码
- 所有写操作后前台缓存刷新
- 删除确认弹窗与空状态

### 7.7 图片上传（UP）

- JPG / PNG / WebP 上传成功
- 超过 5MB 被拒绝
- 非图片被拒绝
- 未登录上传被拒绝
- 上传失败保留表单内容
- Blob 路径符合约定

### 7.8 SEO（SEO）

- 每页 title / description / canonical 正确
- sitemap 包含静态页与已发布内容
- sitemap 不包含草稿、下架商品
- robots 屏蔽后台、登录、API
- 文章 JSON-LD 字段完整
- 404 返回真实 404 状态

### 7.9 统计（STAT）

- 生产环境加载百度统计脚本
- 商品二维码点击事件上报
- 工具官网点击事件上报

### 7.10 安全（SEC）

- 未登录/普通用户无法调用后台 Server Action
- 密码哈希不可逆
- Session Cookie 为 httpOnly / Secure / SameSite
- 登录失败限流有效
- Markdown XSS 被清洗
- 上传类型与大小校验有效
- 不存在明显的越权访问

### 7.11 性能与可访问性（PERF / A11Y）

- 首屏 LCP < 2s
- CLS < 0.1、INP < 200ms
- 1440 / 390 / 320 无水平溢出
- 键盘可完成导航、表单、弹窗操作
- 焦点可见，弹窗焦点陷阱有效
- 图片有 alt，图标按钮有 aria-label
- `prefers-reduced-motion` 生效

## 8. 冒烟测试清单（上线前）

1. 首页可访问，导航与四板块入口正常
2. 文章列表与详情可打开
3. 工具列表与详情可打开
4. 商品详情可打开，微信二维码弹窗正常
5. 关于我页微信信息正确
6. 注册/登录/退出正常
7. 未登录访问 `/studio` 被拒绝
8. 后台发布文章后前台可见
9. 首页精选勾选/取消生效
10. 手机端核心页面布局正常

## 9. 回归策略

- 每次提交：Lint + 单元测试 + 构建
- 每次合并前：相关模块 E2E + 关键路径冒烟
- 每个里程碑：全量 E2E + 视觉回归
- 上线前：全量回归 + Lighthouse + 安全与 SEO 检查
- 修复缺陷后：执行该缺陷用例 + 相关回归用例

## 10. 缺陷分级

| 级别 | 说明 | 示例 | 处理 |
|------|------|------|------|
| P0 | 上线阻断 | 无法登录、后台越权、数据丢失 | 立即修复，修复前不发布 |
| P1 | 严重 | 核心流程不可用、发布不可见、上传失败 | 发布前必须修复 |
| P2 | 一般 | 次要页面错误、样式异常、文案错误 | 评估后修复或排期 |
| P3 | 轻微 | 细节不统一、低优先级体验问题 | 记录后处理 |

## 11. 进入与退出标准

### 进入标准

- 代码可构建、可启动
- 测试环境与测试数据就绪
- 对应需求与详细设计已确认
- 测试用例已编写或更新

### 退出标准

- 所有 P0 / P1 用例通过
- P2 缺陷已评估并记录
- 冒烟测试通过
- 性能、SEO、安全检查通过
- `docs/test-report.md` 已生成

## 12. 测试工具与命令

```bash
npm run lint          # 代码检查
npm run test          # Vitest 单元/集成测试
npm run test:e2e      # Playwright E2E
npm run build         # 生产构建
```

测试代码位置：

- 单元/集成：`tests/unit/`
- E2E：`tests/e2e/`
- 测试数据：`tests/fixtures/`
- 视觉截图：`tests/screenshots/`（不入库）

## 13. 职责与节奏

- 产品/开发/测试：站长一人承担
- 每个功能完成时同步补测试，不把测试全部留到上线前
- 每日开发结束执行单元测试与构建
- 每个阶段结束执行 E2E 与视觉回归
- 上线前输出测试报告

## 14. 风险与应对

| 风险 | 应对 |
|------|------|
| 测试环境与生产环境差异 | 使用 Vercel Preview 做验收，生产只做冒烟 |
| Vercel Blob 测试产生垃圾文件 | 使用 `valuepass/test/` 前缀并定期清理 |
| 百度统计需要真实域名 | Preview/生产环境验证，Local 只验证事件调用 |
| 单人开发导致测试被跳过 | 将测试列入完成定义（Definition of Done） |
| 数据库测试污染生产 | 强制使用独立测试库与测试账号 |
